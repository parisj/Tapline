VisioEval

Configuration-driven evaluation pipeline for continuous data ingestion, processing, and time-windowed analysis

System Architecture

Kafka is the central event hub. Ingest detects files and produces job events. Processing consumes jobs, executes algorithms, and produces metrics back to Kafka. Python Agg (default) or Flink SQL consumes metrics for windowed aggregation and writes directly to MinIO. Aggregate Sink (separate process) runs the metric values collector. Dashboard reads from MinIO and computes AnalysisKind-specific artifacts on-demand. Components marked with ● emit traces and metrics.

Processing Flow

1. Ingest

1Detect new or modified file
2Stability check (file write complete)
3Compute fingerprint
4Check dedup cache
5Publish JOB_CREATED

2. Processing

1Consume JOB_CREATED from Kafka
2Route to algorithm via Dispatcher
3Execute algorithm.run()
4Receive AlgoResult with MetricValues
5Each metric has AnalysisKind flags

3. Analysis

1Filter Kafka events by algo_name, algo_version
2For each metric, evaluate its AnalysisKind flags
3Run matching Analyzers (SUMMARY, DISTRIBUTION_1D, etc.)
4Produce summaries + artifacts for storage
5Prepare results for visualization

4. Storage

1Store artifacts from algorithms
2Store aggregates from Flink
3Content-addressed paths
4Automatic deduplication
5Return ObjectRef metadata

Components

Directory Observer Ingest

Monitors directories for new or modified files.

  • File stability detection
  • Fingerprint-based change detection
  • In-memory dedup cache (1-hour TTL)
  • Per-directory partition key

Event Producer Kafka

Publishes events with cryptographic hash chain.

  • EventEnvelope with content_hash/prev_hash
  • Dual-write to operational + audit topics
  • OpenTelemetry trace propagation
  • Prometheus metrics

Worker Pool Processing

Kafka consumers processing jobs in parallel.

  • Consumer group for load distribution
  • Configurable ThreadPoolExecutor
  • Backpressure via pause/resume
  • Manual offset commit

Algorithm Framework Processing

Extensible interface with lazy initialization.

  • initialize() + run() methods
  • Thread-safe one-time init
  • Version-aware registry
  • Per-algorithm TOML config

Python Aggregation Aggregation

Real-time streaming aggregation (default method).

  • Consumes METRIC_EMITTED events from Kafka
  • 1-min tumbling windows, groups by algo/metric
  • Preserves raw values (numeric, bool, 2D points)
  • Writes directly to MinIO aggregates bucket

Aggregate Sink Storage

Metric values collector (separate process).

  • Runs as separate process (GIL isolation)
  • Auto-restarts on failure
  • Collects raw metric values for analysis
  • Optional: Flink SQL mode consumes visio.aggregates

Evaluation Analyzers Aggregation

AnalysisKind-driven statistical analysis on metric values.

  • Metrics declare analysis via AnalysisKind flags
  • SUMMARY: mean/std/quantiles
  • DISTRIBUTION_1D: histograms
  • OUTLIERS_1D, RATE, ELLIPSE_2D, CONTOUR_2D

MinIO Storage Storage

S3-compatible content-addressed storage.

  • Path format: bucket/ab/cd/{hash}
  • Automatic deduplication
  • Buckets: artifacts, inputs, aggregates
  • ObjectRef metadata tracking

Flask Dashboard Visualization

REST API + web dashboard with dark theme.

  • KPI cards: jobs, throughput, errors, sources
  • Metrics Explorer with Plotly.js charts
  • On-demand artifact computation (histogram, ellipse, contour)
  • Auto-discovers algorithms and metrics from MinIO

Key Features

Event Ordering

Per-partition ordering using directory_key as partition key ensures jobs are processed in order within each directory.

Deduplication

Content-addressed MinIO storage and fingerprint-based cache prevent duplicate processing.

Audit Trail

Per-partition hash chains with dual-write provide tamper-evident event linking.

Exactly-Once

Manual Kafka offset management and Flink checkpointing ensure exactly-once semantics.

Backpressure

Worker pause/resume and consumer group rebalancing handle load gracefully.

Observability

OpenTelemetry tracing, Prometheus metrics, structured logging, and correlation IDs.

AnalysisKind & Value Types

Metrics declare their analysis type via AnalysisKind flags. The system routes them to appropriate Analyzers automatically.

SUMMARY

Numeric statistics: count, mean, median, min, max, std, variance. Value type: float

DISTRIBUTION_1D

Histogram computed on-demand with configurable bins. Value type: float

COUNTER

Categorical frequency table. Value type: bool or str

RATE

Boolean pass/fail rate with Wilson CI. Value type: bool (stored as 0/1)

ELLIPSE_2D

2D covariance ellipse parameters. Value type: {"x": float, "y": float}

CONTOUR_2D

2D density grid for contour plotting. Value type: {"x": float, "y": float}

Audit Trail & Hash Chain

GxP-compliant tamper-evident event linking using SHA-256 cryptographic hash chains.

How It Works

Each EventEnvelope contains:

  • content_hash = SHA-256 of payload (canonical JSON)
  • prev_hash = previous event's content_hash
  • Per-partition chains for ordering guarantees

Verification

To verify chain integrity:

  • Recompute hash from payload - must match content_hash
  • Check event[n].prev_hash == event[n-1].content_hash
  • Any modification or deletion breaks the chain

Benefits

Cryptographic guarantees:

  • Tamper detection - modified events have wrong hash
  • Gap detection - missing events break chain links
  • Order verification - chain enforces sequence
  • Signature-ready for PKI integration
