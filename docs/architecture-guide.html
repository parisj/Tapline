🚀 System Overview

Tapline is a configuration-driven evaluation pipeline for continuous ingestion, processing, and time-windowed analysis of data. It provides a robust, tamper-evident audit trail with cryptographically linked event records.

🏗 System Architecture

The full pipeline spawns three separate processes for optimal performance and isolation:

Main Pipeline main.py
Aggregator flink_aggregation.py
Metric Sink aggregate_sink.py
↓
Kafka Event Transport
MinIO Object Storage

Why Separate Processes?

💪 GIL Bypass

Python's Global Interpreter Lock limits parallelism. Separate processes enable true concurrent execution.

🔄 I/O Isolation

Kafka and MinIO operations are I/O-bound. Process isolation prevents blocking between components.

🔃 Independent Restart

Components can restart independently. The aggregate sink auto-recovers if it crashes.

💡 Why Proxy Through Flask?

All API requests go through Flask to avoid CORS (Cross-Origin Resource Sharing) issues. The browser only talks to one origin (Flask on port 5007), which then proxies requests to MinIO, Prometheus, and other services.

📩 Event System

The event system is the backbone of Tapline. Every action in the pipeline produces an immutable, hash-linked event that forms part of the audit trail.

EventEnvelope Structure

@dataclass(frozen=True)  # Immutable!
class EventEnvelope:
    event_id: str           # UUID - unique identifier
    event_type: EventType   # TASK_CREATED, METRIC_EMITTED, etc.
    source_id: str          # Partition key (directory or algorithm)
    timestamp: datetime     # When event occurred (UTC)
    payload: dict           # Event-specific data
    content_hash: str       # SHA-256 of payload
    prev_hash: str | None   # Link to previous event
    signature: str | None   # For PKI (future)

Event Types

Event Type When Created Payload Contains
TASK_CREATED File discovered by observer path, file_hash, fingerprint, directory_key
TASK_STARTED Worker picks up task processor_name, processor_version
TASK_COMPLETED Processing finished successfully duration_ms, result_count
TASK_FAILED Processing encountered error error_message, traceback
METRIC_EMITTED Processor emits a measurement metric_name, value, aggregation_mask, meta
RESULT_PRODUCED Artifact created and stored artifact_ref, content_type, size

Event Usage Patterns

⚡ Operational Flow

Events drive the pipeline: file discovery triggers TASK_CREATED, which workers consume to start processing, emitting metrics and completing tasks.

📋 Audit Trail

Every event is dual-written to both operational topics and an immutable audit-log topic for tamper-evident replay.

📊 Aggregation Trigger

METRIC_EMITTED events feed the aggregation pipeline, which computes windowed statistics.

🔗 Hash Chain & Tamper Detection

The hash chain creates a cryptographically linked sequence of events. Any modification, deletion, or reordering of events breaks the chain, making tampering detectable.

How Hashing Works

1. Content Hash

Each event's payload is hashed using SHA-256 with canonical (sorted) JSON:

def compute_content_hash(payload: dict) -> str:
    # Canonical JSON ensures deterministic hashing
    canonical = json.dumps(payload, sort_keys=True, default=str)
    return hashlib.sha256(canonical.encode("utf-8")).hexdigest()

2. Chain Linking

Each event stores the previous event's hash, creating an unbroken chain:

# Each new event links to the previous one
new_event = EventEnvelope.create(
    event_type=EventType.TASK_STARTED,
    source_id="path0",
    payload={...},
    prev_hash=previous_event.content_hash  # ← Chain link!
)

File Incorporation

When a file is discovered, its SHA-256 hash is computed and embedded in the TASK_CREATED event:

# File content is hashed and included in event payload
file_hash = hashlib.sha256(file_content).hexdigest()

payload = {
    "task_id": job_id,
    "path": "/data/image.png",
    "file_hash": file_hash,  # ← File bound to event
}
# This payload gets hashed → content_hash includes file_hash
🔒 Cryptographic Binding

The file's content hash is embedded in the event payload, which is then hashed to create the content_hash. This means changing even a single byte of the original file would require modifying the event, which would break the chain.

Tamper Detection

Tampering Type How It's Detected Verification Output
⚠ Payload modified Recomputed hash doesn't match stored content_hash Event N: content_hash mismatch
❌ Event removed Downstream prev_hash points to missing hash Event N: prev_hash mismatch
🔄 Event reordered Chain linkage breaks at reorder point Event N: prev_hash mismatch
➕ Event inserted New event's prev_hash won't match expected Event N+1: prev_hash mismatch
📄 File replaced file_hash in payload won't match file content TASK_CREATED: file_hash mismatch

Chain Verification

from audit.chain import verify_event_chain

# Retrieve events and verify
events = consumer.get_events(source_id="path0")
result = verify_event_chain(events)

if result.valid:
    print(f"Chain valid - {result.event_count} events verified")
else:
    print(f"TAMPERING DETECTED!")
    for error in result.errors:
        print(f"  - {error}")  # Pinpoints exact event
🔑 What's Needed to Verify the Chain
  1. All events in order - Retrieved from Kafka audit-log topic
  2. Original payloads - Stored in event messages
  3. HashChainVerifier - Built into the system
  4. Signature verification - When PKI is enabled (prepared but not yet active)

📈 Aggregation System

The aggregation system computes windowed statistics from metric events. It processes METRIC_EMITTED events and produces summarized data for visualization and analysis.

AggregationType Flags

Each measurement includes a bitmask specifying which aggregation types apply:

Flag Value Description
STATS 1 Compute mean, std, min, max, percentiles
HISTOGRAM 2 Generate distribution histogram
OUTLIERS 4 Detect outlier values (IQR method)
TALLY 8 Simple counting (events per window)
RATE 16 Compute rate of change over time
SCATTER_ELLIPSE 32 2D scatter with confidence ellipse
DENSITY_MAP 64 2D density visualization
RAW 128 Preserve raw values (no aggregation)
